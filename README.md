# Система автоматизации линкбилдинга — пакет проектной документации

Внутренний инструмент для аудита донорских площадок, управления
размещениями и генерации статей под проект convertio.co.

Этот пакет — не ТЗ. Это база, из которой ТЗ пишутся по отдельным
модулям. Каждый эпик разворачивается в ТЗ в момент, когда до него
доходит очередь, а не заранее.

**Версия 1.2 от 23.09.2026.** Проверена целиком: `schema.sql` применена
на PostgreSQL 16.13, представления проверены на тестовых данных, цифры
сверены с выгрузками от 23.09, правила — с промптом аудитора построчно,
документация собрана MkDocs и Zensical, после этого пакет прошёл
независимое ревью отдельным агентом. Что нашли и исправили — в
`PROGRESS.md`, раздел «Проверка пакета».

## Две документации — не путать

| | Проектная | Пользовательская |
|---|---|---|
| Папка | `docs/` | `user-docs/` |
| Про что | как строить систему | как работать с системой |
| Читатель | разработчик и агент | вы в разделе «Документация» интерфейса |
| Когда меняется | при решениях и планировании | с каждой задачей, меняющей то, что видит пользователь |
| Правила | `14-WORKFLOW.md` | `15-USER-DOCS.md` |

Посмотреть пользовательскую документацию локально:

```bash
pip install -r requirements-docs.txt
mkdocs serve          # http://127.0.0.1:8000
python tools/check_user_docs.py
```

## Порядок чтения

**Самое первое:** `14-WORKFLOW.md` — как настроить Project, какие файлы
куда грузить и как переносить знание между чатами. Без него остальное
превратится в кучу документов, которые никто не читает. Сразу за ним —
`16-AGENT-SETUP.md`: поставить Claude Code и подключить PyCharm.

**Первый раз:** `00-VISION` → `02-ARCHITECTURE` → `07-ROADMAP` →
`06-BACKLOG`. Этого хватает, чтобы понять, что строим и с чего
начинаем.

**Каждый раз:** `PROGRESS.md` — где мы сейчас и что дальше.

**Перед кодом:** `03-DATA-MODEL` + `schema.sql` + `13-CONFIG`.

**При работе над конкретной задачей:** файл нужного эпика в
`backlog/` — в нём есть ссылки на всё остальное, что понадобится.

**При споре «почему так»:** `08-DECISIONS`.

## Как разворачивать задачу в ТЗ

1. Открыть новый чат в Project с этим пакетом.
2. Назвать ID задачи: «разворачиваем E1-04 в ТЗ».
3. Я подниму файл эпика, связанные документы по ссылкам из блока
   «Смотри также», задам уточняющие вопросы, если их не хватает, и
   напишу ТЗ по шаблону `docs/templates/spec.md`.

Разбиение бэклога на файлы по эпикам сделано именно ради этого: при
работе над E6 в контекст едет только E6, а не все 62 задачи.

## Дисциплина ведения

- Документы живут в git вместе с кодом, в Project загружается снапшот.
- После каждого значимого решения — запись в `08-DECISIONS.md`.
  Через полгода именно этот файл ответит на вопрос «почему мы сделали так».
- Закрытые вопросы из `09-OPEN-QUESTIONS.md` переезжают в ADR, а не
  просто вычёркиваются.
- Замеры в `10-BASELINE-STATS.md` не редактируются, а дополняются
  новыми на новую дату.
- Каждая задача закрывается по `docs/templates/task-close.md`: код,
  пользовательская документация, `PROGRESS.md`. Это единственный
  механизм, за счёт которого знание накапливается — и между чатами, и
  для пользователей системы.
