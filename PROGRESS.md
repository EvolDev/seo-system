## Где мы сейчас

Локальное окружение готово (E0-01): Django 5.2 в Docker Compose с
Postgres 16 и Redis 7, тесты и проверки — `make test`, `make check`.
Структура на месте (E0-02): шесть доменных приложений в `apps/` (пока
без моделей), настройки local/prod по `DJANGO_ENV`, README проекта.
Логи и ошибки (E0-03): логи в stdout с `run_id` и маскировкой секретов,
ошибки — в GlitchTip (до прода, ADR-026), механизм `run_id` для цепочек.
Пользовательская документация (E0-04): `make docs-check` и
`make docs-serve` в контейнере, pre-commit не пропускает коммит с битой
документацией (ADR-028). Эпик E0 закрыт.
Схема блока 1 (E1-01): продукты, площадки, статус площадки по каждому
продукту (`product_sites`, ADR-030), метрики, цены, серость, аудиты —
модели, миграция, админка со снапшотами. Миграции сверяются со
`schema.sql` тестом (ADR-029).
Схема наблюдаемости (E1-03): журнал проверок `checks` с представлением
просрочек `v_overdue_checks`, вызовы LLM, запуски задач, расход API —
везде `run_id`, по умолчанию из текущей цепочки; таблицы промптов, на
которые ссылается `llm_calls` (ADR-031).
Схема размещений и ключей (E1-02): размещения со ссылками, ключи
продукта и снапшоты позиций — модели, миграции, админка без удаления.
Позиция ссылки в статье считается как «Статистика» Word, два числа — с
пробелами и без (ADR-032, `schema.sql` 1.3).
Импорт таблицы (E1-04): команда `import_workbook` загружает таблицу
ручной работы — площадки, замеры, решения, размещения Convertio и
статьи Clideo, ключи с позициями; сухой прогон, отчёт, одна транзакция,
повторный запуск без дублей. Таблицу ведём до подключения API, импорт
регулярный, главнее админка (ADR-033). Каждая загрузка — рабочий список
площадок (`schema.sql` 1.4). Пометка «реклама» из карточки — не
стоп-фактор (ADR-034). Файл от 27.09 загружен в локальную базу списком
«Сентябрь 2026».
Расчёты и настройки (E1-05): семь отчётных представлений — покрытие
ключей (`links_placed` и `links_waiting` больше не руками), площадка «на
сегодня» с плановыми расходами по порогу продукта, воронка, живость
ссылок, расходы по месяцам; `v_article_funnel` — вместе с таблицами
статей. Настройки `domain_settings`: основные — на странице продукта,
любую общую продукт переопределяет своим значением (ADR-035), общие —
раздел «Настройки». Продукт, с которым не работали, удаляется
(ADR-036).
Админка как база (E9-01): тема django-unfold для всей админки
(ADR-037), экран «Площадки продукта» поверх `v_product_site_latest` —
продукт и самый новый рабочий список по умолчанию, фильтры «уже
работали / новые для нас», статус, DR и трафик диапазоном, язык,
«пишем мы», размещения; поиск по вставленному адресу; 8 запросов на
страницу.
Админка причёсана (E9-08): тема Admin Interface вместо unfold (ADR-038),
четыре расцветки и переключатель **Оформление** в шапке («Apple —
светлая», «Google — тёмная», «Изумрудная», «Ahrefs — тёмная»), переходы
между страницами без моргания (View Transitions), меню по работе —
«Работа / Справочники / Настройки / Служебное», главная с карточками
рабочих экранов, человеческие названия и заголовки. Рабочий экран теперь
называется «Площадки». Тема выбрана на стенде из шести; цвета графиков
для будущего дашборда проверены (ADR-038).
Очередь (E2-01): Celery и Redis — воркер и beat в compose, очередь
Redis переживает перезапуск. Базовый класс задачи `QueueTask`
(`config/queue.py`): `run_id` через очередь, одна строка `task_runs` на
задачу, три попытки — повторы через 1 и 2 минуты, после третьей —
«Ошибка» и событие в GlitchTip; ограничение скорости по ключу в Redis;
задачи не теряются при остановке воркера. Пульс очереди раз в час,
`manage.py queue_check`, экран «Запуски задач» в «Служебном» (ADR-039).
Выдача Google (E2-02): клиент Serper — `search()` из
`apps/integrations/serp`, одинаковый запрос сутки из кеша, каждый
платный запрос сразу в `api_usage`, стоимость — центы с долями
(`numeric`, `schema.sql` 1.5). Дневной лимит ставит задачи на паузу до
полуночи — `Postpone` в `QueueTask`, колонка «пауза» в «Запусках задач».
Экран «Расход API» в «Служебном», `manage.py serp_search`. DataForSEO
отклонён (ADR-040). Оценки «примерно N» у Serper нет — Q20 до E2-06.
Проверка индексации (E2-03): кнопка ↻ в колонке «в индексе», действие
для отмеченных строк и кнопка в карточке — без перезагрузки, ход и итог
всплывающим окном. Статья ищется по `site:`, не нашлась — по самому
адресу; метки вроде `?srsltid` не мешают. По расписанию в 06:00 — кому
подошёл срок (настройка `INDEXATION_SCHEDULE`, пока выключена), 30 дней
не в индексе — одна сводка в день в GlitchTip. Флажок «Не проверять»
(`schema.sql` 1.6). История проверок в карточке (ADR-042).
Продавцы и рабочая цена (E1-07): у площадки цены всех продавцов по датам
(«услуга + цена»), работаем от одной — рабочей, её выбирает человек;
Collaborator — тоже продавец, его цены из таблицы стали рабочими. В
«Площадках» — «цена», «предложения» со стрелками ▲▼, «написание» 📝,
«💬» заметки, фильтры и три действия разбора; карточка площадки окном
без перезагрузки. Заметки — история (`site_notes`), курсы ЕЦБ раз в
день, метрики продавцов — только без доверенных замеров; у размещения —
продавец и сотрудник. `schema.sql` 1.7, ADR-043, прототип экрана
загрузки — `docs/prototypes/price-review.html`.
Загрузка файлов (E1-08): **Работа → Загрузки** — прайс продавца в любом
формате (строка заголовков находится сама, колонки угадываются, разметка
запоминается у продавца) и каталог Collaborator (английская выгрузка,
45 000 строк, перевод значений на русский). Сводка до записи, разбор по
вкладкам с решениями, удалением из базы и блокировкой. У каталога —
«Обновить в базе» и «Добавить новые» по фильтрам (страна, язык, DR,
трафик, цена, dofollow) с облачками и живым счётчиком. Рабочая цена идёт
за новой ценой того же продавца (курс гривны), пока нет заявки в работе.
Экраны загрузки — без перезагрузки страницы. `schema.sql` 1.8, ADR-044.
Каталог от 02.10 загружен в рабочую базу: 4264 площадки.
Выгрузки Ahrefs (E1-10): в **Загрузках** тип «Ahrefs Batch Analysis» —
страна выгрузки с поиском и флагами, сверяется с файлом; «все страны» —
DR, трафик, ключи и топ-регион, страна — трафик и ключи этой страны
(`site_country_metrics`). В «Площадках» — колонка «топ регион» и фильтр
«Регион» (только страны, под которые грузили выгрузку страны) с колонками
и «от — до»; «Домены для Ahrefs» у рабочего списка — файлами по 500. US
Traff из таблицы — в регионе США. Кнопки — от расцветки, наша статика — с
версией в адресе. `schema.sql` 1.9, ADR-045.
Админка без перезагрузки (E9-09): переходы, фильтры, поиск, сортировка,
страницы, формы и действия — подгрузкой (`seo/soft-nav.js`), «Назад»
перечитывает экран и возвращает прокрутку; статус в «Площадках» — окном
«Решение по площадке»; браузерные проверки `make e2e`. ADR-046.
Статусы площадки (E1-12): девять, в порядке окна, фильтра и сортировки —
Новая → Просмотрено → Одобрена → Заявка отправлена → Размещались,
Отбрасываю, Отказала площадка, Чёрный список, На аудите; 62 «Отклонена» —
«Отбрасываю». Статус сам идёт за размещениями, только вперёд: заявка —
«Заявка отправлена», публикация — «Размещались»; новая заявка сильнее
прежнего отказа, чёрный список — никогда. `schema.sql` 1.10, ADR-047.
Записи панелью справа (E9-11): размещения, «Площадки», каталог, продавцы,
ключи, рабочие списки, продукты, настройки — щелчок по записи открывает её
панелью поверх списка, шириной по содержимому; «Сохранить» — строка списка
меняется на месте, ↑/↓ — соседняя запись, несохранённые правки — вопрос;
«Добавить» — тоже панелью; карточка площадки и решение — в той же панели,
статусы кнопками. Форма размещения: статус кнопками, даты днём с
«Сегодня», «Заплачено» в валюте, кнопка статуса ставит сегодняшнюю дату.
ADR-048.

Ближайшая цель: **первый вертикальный срез** (фаза 1) — импортировать
рабочую базу и пул в Postgres, увидеть площадки в админке, нажать кнопку
«проверить индексацию» и получить результат. После этого Excel перестаёт
быть рабочим инструментом.

**Таблица ручной работы** — `Линкбилдинг Convertio.co.xlsx` в корне
проекта (в git не идёт). Загружать — `import_workbook` с датой выгрузки
и именем списка, сначала `--dry-run`; как читать отчёт — инструкция
«Как загрузить таблицу в систему».

## Принятые решения

48 записей ADR в `docs/08-DECISIONS.md`. Ключевые:

- **ADR-002** — Python + Django, не PHP.
- **ADR-003** — ORM для объектов, сырой SQL для отчётов.
- **ADR-005** — никакого дообучения модели, «обучение» через библиотеку
  примеров и веса.
- **ADR-016** — детерминированные проверки делает код, LLM — тест на
  извлечение и естественность.
- **ADR-017** — уникальность контента критична с первой версии.
- **ADR-020** — предфильтр по полям Collaborator до любых платных вызовов.
- **ADR-021** — пользовательская документация в репозитории, MkDocs.
- **ADR-022** — эмбеддинги через Voyage AI: своей модели у Anthropic нет.
- **ADR-023** — пакеты через uv, тесты и проверки — в контейнере.
- **ADR-024** — приложения в `apps/`, настройки local/prod по `DJANGO_ENV`.
- **ADR-025** — логи, `run_id`, Sentry — в `config/`; stdlib `logging`.
- **ADR-026** — ошибки до прода в GlitchTip, в проде — sentry.io.
- **ADR-027** — convertio-ai-editor — отдельная система; читает наш
  срез `ai_editor_sites` под ролью только на чтение.
- **ADR-028** — pre-commit; хук запускает `make docs-check` в
  контейнере; зависимости документации — группа `docs` в `pyproject.toml`.
- **ADR-029** — как модели Django повторяют `schema.sql`; сверка тестом.
- **ADR-030** — несколько продуктов: факты о площадке общие, решение —
  у продукта.
- **ADR-031** — таблицы промптов делает E1-03; `run_id` по умолчанию
  из текущей цепочки — и у размещений (уточнение E1-02).
- **ADR-032** — позиция ссылки в статье как «Статистика» Word,
  заголовок входит; два числа — с пробелами (по нему правила) и без.
- **ADR-033** — импорт таблицы регулярный, главнее админка: факты
  каталога перезаписываются, замеры — снапшот на дату, решения и
  размещения только дополняются; каждая загрузка — рабочий список.
- **ADR-034** — пометка «реклама» в карточке Collaborator не
  стоп-фактор: она оговорена заранее; нарушение — неоговорённая пометка
  на нашей статье.
- **ADR-035** — любую известную настройку продукт переопределяет своим
  значением; стёртое локальное значение удаляется, продукт возвращается
  к общему; список ключей — в коде.
- **ADR-036** — продукт, с которым не работали, удаляется вместе с
  пустыми строками «продукт × площадка» и настройками.
- **ADR-037** — список площадок продукта поверх `v_product_site_latest`;
  тема django-unfold заменена (ADR-038).
- **ADR-038** — тема Admin Interface; четыре расцветки нашим слоем CSS с
  переключателем «Оформление»; View Transitions; меню по работе человека
  (`config/admin_site.py`); проверенные цвета графиков к E9-03.
- **ADR-039** — очередь Celery + Redis; базовый класс `QueueTask`:
  `run_id`, одна строка `task_runs` на задачу, 3 попытки, алерт —
  событие в GlitchTip (Telegram — E9-04); ограничение скорости по ключу
  в Redis; задачи не теряются при остановке воркера.
- **ADR-040** — выдача Google через Serper (DataForSEO отклонён);
  расход API — центы с долями (`numeric`); кеш на сутки, дневной лимит —
  пауза задачи `Postpone` до полуночи; экран «Расход API».
- **ADR-041** — своя база площадок из всех источников: продавцы (и
  Collaborator), цены по продавцам на дату, «где дешевле» — публикация
  против публикации в евро по курсу ЕЦБ; из файлов ничего не теряется;
  метрики продавца — только без наших; заметки — история; загрузка
  файлов с памятью разметки у продавца; сотрудники — пользователи.
- **ADR-042** — проверка индексации: `site:`, не нашлась — по самому
  адресу; метки отслеживания в адресе не мешают; выдача мимо кеша;
  сроки — `INDEXATION_SCHEDULE` от полуночи, заведена выключенной;
  «Не проверять»; алерт — одна сводка в день (GlitchTip до E9-04).
- **ADR-043** — рабочая цена площадки (`sites.price_id`, одна на все
  продукты, меняет человек, смена — заметка); предложение — «продавец +
  услуга + цена» в `site_prices`, разбор через `reviewed_at`;
  сравниваются только цены размещения одной услуги в евро по курсу ЕЦБ;
  метрики — доверенные источники; заметки — история; карточка окном.
- **ADR-044** — загрузка файлов: `uploads`, строки разбора, разметка у
  продавца, каталог Collaborator с переводом значений; рабочая цена идёт за
  новой ценой того же продавца, пока нет заявки в работе; порог
  `OFFER_RECHECK`; у каталога — «Обновить в базе» и «Добавить новые» с
  фильтрами; удалить из базы и заблокировать в разборе; один продукт —
  одна площадка.
- **ADR-045** — выгрузки Ahrefs Batch Analysis: тип загрузки без
  продавца со страной; «все страны» — `site_metrics` с топ-регионом,
  страна — `site_country_metrics`; регион в «Площадках» — только из
  выгрузок страны; US Traff — в регион; источник `ahrefs_batch`; флаги и
  названия стран; наша статика — с версией в адресе.
- **ADR-046** — админка без перезагрузки: свой общий скрипт
  `seo/soft-nav.js`, не HTMX `hx-boost`; окно «Решение по площадке»;
  браузерные проверки `make e2e`.
- **ADR-047** — девять статусов площадки в порядке окна (тип создан
  заново), «Отклонена» → «Отбрасываю», отказ площадки — `declined`;
  статус по размещениям только вперёд, новый факт сильнее отказа и
  аудита, чёрный список — никогда; импорт — те же правила.
- **ADR-048** — записи панелью справа поверх списка: одна панель на все
  списки, форма с сервера по `X-Seo-Partial`, запись — JSON, строка
  списка меняется на месте; ширина по содержимому; поля под удобство —
  `config/forms.py`.

## Технический долг и известные проблемы

- Ошибки до прода идут в GlitchTip, не в sentry.io (ADR-026): с машины
  разработчика sentry.io недоступен. При E10-02 переключить прод на
  Sentry и проверить `manage.py observability_check --raise` — Q15.
- Заметность ссылки (`LINK_NOT_VISIBLE`) в v1 проверяет человек.
  Автоматизация требует headless-браузера — отдельная задача, когда
  дойдут руки.
- Копирование из Claude Code в терминале PyCharm: в `/etc/wsl.conf`
  выключен interop, поэтому встроенное копирование не доходит до буфера
  Windows. Обход — выделять с `Shift` или `/tui default`. Дописать в
  `16-AGENT-SETUP.md` §9.
- PyCharm не видит интерпретаторы в WSL: при добавлении интерпретатора
  «No interpreters were found» (даже системного `/usr/bin/python3`),
  кнопки выбора файла не работают. Возможно, связано с выключенным
  interop в `/etc/wsl.conf` — не проверено. Нужен только для подсказок
  IDE: проверки идут в контейнере. Путь к окружению —
  `/mnt/r/web/www/seo-system/.venv/bin/python`.
- Движок документации — MkDocs 1.6 с ограничением `<2`. Переход на
  Zensical, когда он выйдет в 1.0 (`15-USER-DOCS.md` §6.1).
- Общие значения `domain_settings` заполняет E5-02 (фаза 4a), а читают
  их раньше: `GRAY_TERMS` — E2-06 (фаза 2), зоны — E4 (фаза 3). Таблица
  и раздел «Настройки» есть с E1-05, значения до E5-02 придётся вводить
  руками в админке или перенести заполнение общих значений раньше.
  Решить до E2-06.
- Таблицы промптов есть с E1-03 (ADR-031), но админки для них и выбора
  варианта («локальный шаблон перекрывает общий») нет ни в одной
  задаче. Нужны к E4-01: без них промпт аудитора некуда ввести.
- `keywords.tool` не сверяется со списком `TOOL_CATEGORIES` продукта:
  настройка есть с E1-05, а проверки нет ни в одной задаче.
  Опечатка в разделе («Vidoe») пройдёт молча, и ключ выпадет из
  фильтров по разделу. Добавить проверку в форму ключа после E1-05.
- Контрольные числа предфильтра (848 из 1494, `10-BASELINE-STATS.md`
  §8.3, ADR-020, E4-05) посчитаны по выгрузке 23.09 и с пометкой
  «реклама» как условием, которое отменено (ADR-034). Пересчитать по
  текущей базе при планировании E4-05.
- «База Starmedia» (679 площадок другого продавца, свой формат, цены в
  $) загрузится как прайс продавца в E1-08 (ADR-041). «Дополнительные
  площадки» (контакты линкбилдеров) импортом не загружаются.
- Таблицы статей (`articles`, `article_versions`, `article_reviews`,
  `validation_results`) не создаёт ни одна задача: E6-01 уже пишет в
  `articles.brief`, E7-01 — в `validation_results`. Вместе с ними —
  `v_article_funnel` (из E1-05 перенесено). Назначить задачу до E6-01.
- `site_audits.run_id` заполняется только явно. У таблиц наблюдаемости
  он по умолчанию берётся из текущей цепочки (ADR-031) — сделать так же
  к E4, где аудит пишется из цепочки.
- Моргание при переходах между страницами в Opera (в Edge нет): View
  Transitions включены (ADR-038). Если после проверки настроек браузера
  (приватное окно, принудительная тёмная тема, блокировщик) останется —
  разобраться отдельно.
- Хлебные крошки без уровня приложения Django — только в списках и
  формах. На страницах истории и подтверждения удаления они штатные, со
  средней крошкой-приложением («Площадки»).
- Очередь в прод-compose (E10-01): том для состояния beat (иначе
  пропущенный из-за перезапуска запуск не догоняется), Redis с AOF и
  томом, число процессов воркера и время на его остановку (ADR-039).
- Проверщик документации (`tools/check_user_docs.py`) и хук pre-commit
  берут «сегодня» по часам контейнера — UTC. С 00:00 до 03:00 по Москве
  сегодняшняя дата в `updated` для них «из будущего», и коммит не
  проходит. Поправить: `TZ` контейнеров из `TIME_ZONE` или дата в
  проверщике по `TIME_ZONE`. У страниц E2-01 из-за этого
  `updated: 2026-09-28`.
- `llm_calls.cost_cents` пока `integer`: вызов дешёвой модели стоит доли
  цента и округлится до нуля. Перевести на `numeric(14,4)`, как
  `api_usage`, в E4-01 (ADR-040).
- Строка `api_usage` пишется в транзакции того, кто ищет: если задача
  откатит свою транзакцию после `search()`, деньги потрачены, а строки
  нет. Индексация (E2-03) ищет до транзакции записи; в E2-06 — так же.
- Состояние проверки для кнопок ищется по `task_runs.payload->>'task_id'`
  без индекса (окно — сутки, `task_name` в индексе). При ~700 строк в
  день незаметно; если экран начнёт тормозить — индекс по выражению.
- Сводка оповещений берёт пометки с начала прошлого удачного запуска:
  пометка, записанная в те же миллисекунды, когда шла прошлая сводка,
  попадёт в две сводки подряд. Потерь нет, повтор возможен.
- Статьи без даты публикации (599 из 651) считают «30 дней не в индексе»
  от первой неудачной проверки: давно мёртвая статья даст оповещение не
  сразу, а через 30 дней после включения расписания.
- Два одинаковых запроса одновременно (кеша ещё нет) оба идут к Serper и
  оба платятся. Для индексации несущественно; для массового gray scan
  (E2-06) — замок на ключ кеша (`cache.add`).
- «Площадки» на 45 000 площадок каталога (рабочие данные на копии, E1-08):
  1,8 с, из них подсчёт строк для страниц — 0,6 с, сортировка по цене —
  1,8 с; «есть новые» — 0,5 с, «есть дешевле» — 1 с. Заметки уже одним
  подзапросом (было 3,4 с). Дальше: подсчёт для страниц — приблизительный;
  флаги «есть новые» и «дешевле» — сводным запросом с проверкой плана
  (вариант E1-07 дал фильтр «дешевле» за 2 минуты); `v_site_offers`
  сортирует все снимки цен — растёт с каждой выгрузкой (см. ниже).
- Снимки каталога растут: каждая загрузка — до 45 000 строк цен (с
  прочими данными) и метрик и столько же строк разбора; при трёх
  выгрузках в месяц — около 2 ГБ в год. `v_site_offers` (DISTINCT ON по
  всем снимкам цен) и с ним «Площадки» со временем замедлятся. Решить
  до того, как снимков станет миллионы: индекс под «последнее
  предложение», прочие данные — только при изменении.
- Площадки, которых нет в свежей выгрузке каталога (87 из базы на
  01.10.2026), никак не помечаются — их цена Collaborator уже
  недействительна. Пометка «нет в каталоге» — при планировании E1-10 или
  E9-02.
- Топ-гео пропадает у площадки, где последний доверенный замер — от
  каталога (в каталоге гео нет): `v_site_latest` берёт замер целиком.
  Брать гео из последнего замера, где оно есть, — E1-10.
- Прод (E10-01): общий том для `uploads/` (файлы видит воркер), лимит
  размера запроса веб-сервера под файл каталога (18 МБ), кеш Redis под
  строки фильтров (несколько МБ на загрузку, 7 дней).
- Функция `eur_rate()` (SQL) Postgres не встраивает в запрос: вызов на
  каждую строку. На 40 000 площадок разница с встроенным пересчётом
  незаметна (замер E1-07), но при оптимизации «Площадок» — кандидат.
- Продавец у нового размещения не подставляется из рабочей цены
  площадки — заполняется руками. Подставлять — в E1-09, когда размещения
  пойдут из файлов.
- Статика без заголовков кеширования: с E1-10 наши CSS и JS — с версией
  в адресе (`config/assets.py`), но картинки из CSS (`sprite-hq.png`,
  `globe.svg`) и статика пакетов — без неё. В проде — имена с хешем
  (ManifestStaticFilesStorage, E10-01).
- В «Загрузках» таблица шире колонки: «состояние», «рабочий список» и
  дата загрузки уходят вправо за прокрутку.
- Цифры US Traff из таблицы перенесены как были: у части площадок трафик
  США больше общего (tycoonstory.com — 729 410 при 347 737) — так в
  таблице от 26.09.
- Список регионов в «Площадках» считает площадки по всем снимкам
  `site_country_metrics`, удалённые тоже — расхождение в единицы.
- Автодополнение площадки в форме размещения выдаёт предупреждение Django
  `UnorderedObjectListWarning`: у выборки площадок нет порядка, и страницы
  подсказок могут повторять и терять площадки (видно в `make e2e`, E9-09).
- Браузерные проверки (`make e2e`) — только Chromium: Opera и Edge того же
  движка, но эффекты (плавная смена, моргание) сверять в обоих руками.
- `QuerySet.update()` статуса размещения обходит смену статуса площадки
  (ADR-047, `Placement.save()`). Сейчас таких мест нет; массовая смена
  статуса размещений (E9-11, E1-09) — сохранением по одному или с вызовом
  `statuses.advance()`.
