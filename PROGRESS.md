## Где мы сейчас

Локальное окружение готово (E0-01): Django 5.2 в Docker Compose с
Postgres 16 и Redis 7, тесты и проверки — `make test`, `make check`.
Структура на месте (E0-02): шесть доменных приложений в `apps/` (пока
без моделей), настройки local/prod по `DJANGO_ENV`, README проекта.
Логи и ошибки (E0-03): логи в stdout с `run_id` и маскировкой секретов,
ошибки — в GlitchTip (до прода, ADR-026), механизм `run_id` для цепочек.
Пользовательская документация (E0-04): `make docs-check` и
`make docs-serve` в контейнере, pre-commit не пропускает коммит с битой
документацией (ADR-028). Эпик E0 закрыт.
Схема блока 1 (E1-01): продукты, площадки, статус площадки по каждому
продукту (`product_sites`, ADR-030), метрики, цены, серость, аудиты —
модели, миграция, админка со снапшотами. Миграции сверяются со
`schema.sql` тестом (ADR-029).
Схема наблюдаемости (E1-03): журнал проверок `checks` с представлением
просрочек `v_overdue_checks`, вызовы LLM, запуски задач, расход API —
везде `run_id`, по умолчанию из текущей цепочки; таблицы промптов, на
которые ссылается `llm_calls` (ADR-031).
Схема размещений и ключей (E1-02): размещения со ссылками, ключи
продукта и снапшоты позиций — модели, миграции, админка без удаления.
Позиция ссылки в статье считается как «Статистика» Word, два числа — с
пробелами и без (ADR-032, `schema.sql` 1.3).
Импорт таблицы (E1-04): команда `import_workbook` загружает таблицу
ручной работы — площадки, замеры, решения, размещения Convertio и
статьи Clideo, ключи с позициями; сухой прогон, отчёт, одна транзакция,
повторный запуск без дублей. Таблицу ведём до подключения API, импорт
регулярный, главнее админка (ADR-033). Каждая загрузка — рабочий список
площадок (`schema.sql` 1.4). Пометка «реклама» из карточки — не
стоп-фактор (ADR-034). Файл от 27.09 загружен в локальную базу списком
«Сентябрь 2026».
Расчёты и настройки (E1-05): семь отчётных представлений — покрытие
ключей (`links_placed` и `links_waiting` больше не руками), площадка «на
сегодня» с плановыми расходами по порогу продукта, воронка, живость
ссылок, расходы по месяцам; `v_article_funnel` — вместе с таблицами
статей. Настройки `domain_settings`: основные — на странице продукта,
любую общую продукт переопределяет своим значением (ADR-035), общие —
раздел «Настройки». Продукт, с которым не работали, удаляется
(ADR-036).
Админка как база (E9-01): тема django-unfold для всей админки
(ADR-037), экран «Площадки продукта» поверх `v_product_site_latest` —
продукт и самый новый рабочий список по умолчанию, фильтры «уже
работали / новые для нас», статус, DR и трафик диапазоном, язык,
«пишем мы», размещения; поиск по вставленному адресу; 8 запросов на
страницу.
Админка причёсана (E9-08): тема Admin Interface вместо unfold (ADR-038),
четыре расцветки и переключатель **Оформление** в шапке («Apple —
светлая», «Google — тёмная», «Изумрудная», «Ahrefs — тёмная»), переходы
между страницами без моргания (View Transitions), меню по работе —
«Работа / Справочники / Настройки / Служебное», главная с карточками
рабочих экранов, человеческие названия и заголовки. Рабочий экран теперь
называется «Площадки». Тема выбрана на стенде из шести; цвета графиков
для будущего дашборда проверены (ADR-038).
Очередь (E2-01): Celery и Redis — воркер и beat в compose, очередь
Redis переживает перезапуск. Базовый класс задачи `QueueTask`
(`config/queue.py`): `run_id` через очередь, одна строка `task_runs` на
задачу, три попытки — повторы через 1 и 2 минуты, после третьей —
«Ошибка» и событие в GlitchTip; ограничение скорости по ключу в Redis;
задачи не теряются при остановке воркера. Пульс очереди раз в час,
`manage.py queue_check`, экран «Запуски задач» в «Служебном» (ADR-039).
Выдача Google (E2-02): клиент Serper — `search()` из
`apps/integrations/serp`, одинаковый запрос сутки из кеша, каждый
платный запрос сразу в `api_usage`, стоимость — центы с долями
(`numeric`, `schema.sql` 1.5). Дневной лимит ставит задачи на паузу до
полуночи — `Postpone` в `QueueTask`, колонка «пауза» в «Запусках задач».
Экран «Расход API» в «Служебном», `manage.py serp_search`. DataForSEO
отклонён (ADR-040). Оценки «примерно N» у Serper нет — Q20 до E2-06.
Проверка индексации (E2-03): кнопка ↻ в колонке «в индексе», действие
для отмеченных строк и кнопка в карточке — без перезагрузки, ход и итог
всплывающим окном. Статья ищется по `site:`, не нашлась — по самому
адресу; метки вроде `?srsltid` не мешают. По расписанию в 06:00 — кому

Продавцы и рабочая цена (E1-07): у площадки цены всех продавцов по датам

загрузки — `docs/prototypes/price-review.html`.

Экраны загрузки — без перезагрузки страницы. `schema.sql` 1.8, ADR-044.

Размещения из файлов и ссылающиеся домены (E1-09): в **Загрузках** — тип

продукт и «от кого», разметка с памятью по прошлым таким загрузкам.
Размещение дополняется, а не дублируется — одно правило с импортом таблицы;

1.13, ADR-051.
Выгрузка в Excel (E1-06): над «Площадками» и «Размещениями» — окно

Серость площадки (E2-06): в карточке площадки раздел «Серость в Google» —
кнопки **Google: всего страниц** (`site:домен`) и **Google: серые темы**

Счета продавцов (E1-14): **Работа → Счета** — счёт на одно размещение или пачку,
сумма делится поровну до цента или по вписанным долям, ссылка на оплату, статус
«Выставлен / Оплачен / Отменён», кто и когда оплатил. «Заплачено» размещения в
счёте ставит счёт — руками, импортом и загрузкой не правится. «Счёт на
отмеченные» в «Размещениях» открывает счёт панелью; фильтр и колонка «счёт»; у
продавца — к оплате и заплачено. Выгрузка — в виде листа «Счета», в отчёте за
месяц — колонки счёта, лист «Счета» читает импорт таблицы. Главная — одним
экраном на всю ширину: карточки работы, статистика (размещено и потрачено за
месяц, графики по месяцам года по продукту, без перезагрузки), разделы меню
колонками. Статус, поставленный в панели, в строке списка меняется сразу,
остальные ячейки приходят в фоне одной строкой, и у строки, которая больше не
подходит под фильтры. `schema.sql` 1.14, ADR-055.
Документация в системе (E9-07): **Документация** в шапке рядом с «Оформлением» —
сайт MkDocs в новой вкладке, только после входа, поиск по-русски; «?» у названия
экрана и в шапке панели записи — справка по экрану, меню страниц, первыми —
только про этот экран; «Что нового» внизу главной — верхний раздел журнала с
записями (до первого выпуска — «Не выпущено»). Сайт собирается при сборке образа
в `/opt/user-docs`, битая документация не даёт образу собраться; локально раздел
обновляет `make up`. ADR-056.
Рабочий продукт и списки на месте (E9-12): фильтр, сортировка, страницы и поиск
меняют только строки, счётчики и отметки фильтров — экран не мигает, набранное в
поиске, «Действие», «продавец», недописанные «от — до» не стираются; по поиску
список отбирается только по «Найти». В шапке рядом с «SEO-система» — рабочий
продукт, у каждого свой (`user_settings`): с ним открываются экраны с фильтром
продукта и главная, он в новых записях; «Все» в фильтре — явным выбором. В
«Размещениях» — «Адрес страницы» и «Проверить»: окошко вверху справа «В индексе» /
«Не в индексе», без записи. `schema.sql` 1.15, ADR-057.
Карточка площадки (E9-13): закреплённая шапка — домен, шесть плиток (DR, трафик,
топ-регион, язык, серость, рабочая цена), решение по рабочему продукту первым,
вкладки разделов; разделы блоками, сворачиваются в строку со сводкой — выбор у
пользователя в базе (`user_settings.card_closed`), на все карточки. Заметки
лентой: ник, продукт, «сегодня, 12:45», «Система» — заметки из файлов, Ctrl+Enter.
`schema.sql` 1.16, ADR-058.
Анкоры продукта (E3-05): **Справочники → Анкоры** — лист «Распределение анкоров»
целиком (объёмы, Placed, Waiting, позиции по датам, Tool, Type) и доли «цель /
факт» по типам страниц с правкой в ячейке, безанкорка, страны. У ссылки
размещения — «Анкор» с поиском и «Куда ведёт» из анкора, новый анкор — окном,
номер ссылки сам; над ссылками — итоги, доли и 10 рекомендаций по недобору долей.
Загрузки → «Анкоры продукта» — файл и листы долей сводятся с базой, ничего не
стирая; тот же разбор у импорта таблицы. Безанкорка — строки `keywords` со своими
типами. `schema.sql` 1.17, настройка `ANCHOR_RECOMMEND`, ADR-059.

Удаление и отмена загрузки (E1-15, E1-16): удалить можно любую запись,
подтверждение показывает, что уйдёт вместе с ней и где только очистится ссылка
(`config/deletion.py`). У загрузки — журнал изменений (`upload_changes`, триггер
на 25 рабочих таблицах, `schema.sql` 1.18): кнопка «Отменить загрузку» возвращает
прежние значения, убирает созданное и сам файл, после чего тот же файл грузится
заново. Поверх отменённой лежит более поздняя — сначала отменяют её. Файл
размещений другого продукта больше не записывается: строки, где все ссылки ведут
на другой продукт, пропускаются, а сводка говорит «Похоже, это файл «Clideo»».
На шаге колонок — галочка «грузить», цена из файла размещений идёт через разбор,
как у прайса, в фильтре «продавец» у имени — число площадок при остальных
фильтрах. ADR-060.

Слияние продавцов (E1-17): в «Продавцах» — действие «Объединить продавцов…»,
экран слияния графом (щелчок делает главным, наведение показывает подробности,
галочка выводит из слияния). На главного переезжают цены, замеры, загрузки,
размещения и счета; одинаковые цены схлопываются с переводом ссылок; Collaborator
сливать в другого нельзя. ADR-061.

## Принятые решения

59 записей ADR в `docs/08-DECISIONS.md`. Ключевые:

- **ADR-002** — Python + Django, не PHP.
- **ADR-003** — ORM для объектов, сырой SQL для отчётов.
- **ADR-005** — никакого дообучения модели, «обучение» через библиотеку

- **ADR-016** — детерминированные проверки делает код, LLM — тест на
  извлечение и естественность.
- **ADR-017** — уникальность контента критична с первой версии.
- **ADR-020** — предфильтр по полям Collaborator до любых платных вызовов.
- **ADR-021** — пользовательская документация в репозитории, MkDocs.
- **ADR-022** — эмбеддинги через Voyage AI: своей модели у Anthropic нет.
- **ADR-023** — пакеты через uv, тесты и проверки — в контейнере.
- **ADR-024** — приложения в `apps/`, настройки local/prod по `DJANGO_ENV`.
- **ADR-025** — логи, `run_id`, Sentry — в `config/`; stdlib `logging`.
- **ADR-026** — ошибки до прода в GlitchTip, в проде — sentry.io.
- **ADR-027** — convertio-ai-editor — отдельная система; читает наш
  срез `ai_editor_sites` под ролью только на чтение.

  контейнере; зависимости документации — группа `docs` в `pyproject.toml`.
- **ADR-029** — как модели Django повторяют `schema.sql`; сверка тестом.
- **ADR-030** — несколько продуктов: факты о площадке общие, решение —
  у продукта.
- **ADR-031** — таблицы промптов делает E1-03; `run_id` по умолчанию
  из текущей цепочки — и у размещений (уточнение E1-02).
- **ADR-032** — позиция ссылки в статье как «Статистика» Word,
  заголовок входит; два числа — с пробелами (по нему правила) и без.

- **ADR-034** — пометка «реклама» в карточке Collaborator не
  стоп-фактор: она оговорена заранее; нарушение — неоговорённая пометка

- **ADR-035** — любую известную настройку продукт переопределяет своим
  значением; стёртое локальное значение удаляется, продукт возвращается
  к общему; список ключей — в коде.
- **ADR-036** — продукт, с которым не работали, удаляется вместе с

## Технический долг и известные проблемы

- Анкоры (E3-05): загрузка «Анкоры продукта» проверена модульными тестами и на
  копии базы, браузерного e2e пути загрузки нет. Выгрузки списка «Анкоры» в Excel
  нет (кнопка «Выгрузить ▾» требует колонок экспорта). Разбавленные анкоры —
  только доля в таблице, самих анкоров и места в подборе нет. Доли по странам
  только показываются. Подпись Django у ссылок — «Добавить еще один Ссылка».
- `make e2e` стирает `test-results/` целиком — снимки самопроверки держать вне
  этой папки или снимать после прогона.
- Убитый на полпути прогон оставляет базу `test_seo`, и следующий падает на
  всех тестах с «database "test_seo" already exists». Лечится до запуска:
  `docker compose exec postgres psql -U ... -d postgres -c 'DROP DATABASE test_seo'`.

- Отмена и удаление (E1-15, E1-16): браузерного e2e пути нет — проверено
  модульными тестами. Удаление необратимо, «корзины» нет: вернуть запись можно
  только из копии базы. Выбора продукта у строки прямо в сводке загрузки нет —
  строки чужого продукта пропускаются целиком; если понадобится грузить файл с
  размещениями двух продуктов сразу, это отдельная задача.

- Проверка адреса (E9-12) при исчерпанном дневном лимите Serper встаёт на паузу
  до полуночи: окошко говорит «отложена», а итог после полуночи никто не
  увидит — он живёт в кеше 15 минут. Если станет мешать — отказывать сразу.
- Панель записи с несохранёнными правками закрывается молча при смене фильтра
  выпадающим списком (вопрос задаётся только при щелчке по ссылке) — так было и
  до E9-12.
- Плагин pytest-playwright при любом запуске pytest очищает `test-results/`:
  логи прогонов и временные скрипты держать в scratchpad.
- Строка списка одной записью (`_seo_row`, ADR-048) на «Площадках» отвечает
  0,5 с: время уходит на фильтры колонки справа, которые строке не нужны. Если
  станет заметно — не строить фильтры в режиме строки.
- Счета из листа «Счета» записываются оплаченными без даты оплаты: в листе
  дат нет. В фильтр «оплачен» по месяцам они не попадают.

- Ошибки до прода идут в GlitchTip, не в sentry.io (ADR-026): с машины
  разработчика sentry.io недоступен. При E10-02 переключить прод на
  Sentry и проверить `manage.py observability_check --raise` — Q15.
- Заметность ссылки (`LINK_NOT_VISIBLE`) в v1 проверяет человек.
  Автоматизация требует headless-браузера — отдельная задача, когда

- Движок документации — MkDocs 1.6 с ограничением `<2`. Переход на

- Общие значения `domain_settings` заполняет E5-02 (фаза 4a), а читают

- Статика без заголовков кеширования: с E1-10 наши CSS и JS — с версией
