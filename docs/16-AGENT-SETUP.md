# 16. Рабочее место: WSL, Claude Code, PyCharm

Разовая настройка перед первой задачей. Сверено с документацией
Claude Code и JetBrains на 23.09.2026.

Итоговая схема: проект лежит в файловой системе WSL, Claude Code
установлен в WSL, PyCharm на Windows открывает проект по сетевому пути
WSL, его встроенный терминал — это терминал WSL, в нём запускается
`claude`, и плагин показывает правки агента во встроенном просмотрщике
изменений PyCharm.

---

## 0. Что должно быть до начала

- **WSL 2**, не WSL 1. Проверка в PowerShell: `wsl -l -v`, в колонке
  VERSION должно стоять `2`. Там же видно имя дистрибутива — ниже везде
  `Ubuntu`, подставь своё.
- **Платный план Claude** — Pro, Max, Team, Enterprise — или аккаунт
  Console. Бесплатный план не даёт доступа к Claude Code.
- **Docker** с доступом из WSL: `docker compose version` в терминале WSL
  должен ответить версией. Если нет — Docker Desktop, в нём Settings →
  Resources → WSL integration → включить для своего дистрибутива.
- **PyCharm** — актуальная версия.

## 1. Проект — в файловую систему WSL

Не в `/mnt/c/...`. Файлы на диске Windows WSL читает через медленный
мост: git, pytest и Docker будут заметно тормозить. Microsoft советует
держать проект в файловой системе Linux, если работаешь
Linux-инструментами.

```bash
sudo apt install -y unzip git
git config --global user.name "Имя"          # если git ещё не настроен
git config --global user.email "почта@example.com"
mkdir -p ~/projects && cd ~/projects
unzip /mnt/c/Users/<имя в Windows>/Downloads/seo-linkbuilding-system-docs.zip
cd seo-system
git init
git add .
git commit -m "docs: пакет проектной документации v1.2"
```

Путь проекта дальше: `~/projects/seo-system`.

## 2. Claude Code в WSL

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version
claude doctor
```

`claude doctor` проверяет установку и настройки, сессию не запускает.
Нативная установка обновляется сама в фоне.

Первый вход: `claude` в папке проекта, дальше по подсказкам в браузере.
Если браузер из WSL не открылся — скопируй ссылку из терминала вручную.

При первом запуске в папке Claude Code спросит, доверяешь ли ты ей, —
ответить «да», это твоя папка. Запреты из `.claude/settings.json`
действуют в любом случае, а вот разрешения, если они там появятся,
применяются только после доверия.

## 3. PyCharm

### 3.1. Открыть проект из WSL

File → Open → `\\wsl.localhost\Ubuntu\home\<пользователь>\projects\seo-system`
(на старых сборках Windows — `\\wsl$\Ubuntu\...`).

### 3.2. Встроенный терминал — WSL

Settings → Tools → Terminal → Shell path: `wsl.exe -d Ubuntu`.

Открой терминал в PyCharm и проверь `pwd` — должно быть
`/home/<пользователь>/projects/seo-system`. Если нет — `cd` туда.

Там же, в Settings → Tools → Terminal, сними галку «Move focus to the
editor with Escape». Иначе Esc не будет прерывать агента, а переключит
фокус в редактор.

### 3.3. Плагин Claude Code

Settings → Plugins → Marketplace → **Claude Code [Beta]** → установить,
перезапустить PyCharm. Плагин не содержит своей копии агента, он
запускает `claude` из терминала — поэтому шаг 2 обязателен.

Settings → Tools → Claude Code [Beta] → **Claude command**:

```
wsl -d Ubuntu -- bash -lic "claude"
```

Это нужно для кнопки и сочетания Ctrl+Esc; из терминала `claude`
работает и без этого.

### 3.4. Проверить связь

Во встроенном терминале: `claude`. В сессии: `/ide` — ожидаемый ответ
вида `Connected to PyCharm`.

Если ответ **No available IDEs detected** — WSL 2 в режиме NAT не
пускает агента к PyCharm на Windows. Два способа починить:

- **Windows 11 22H2 и новее** — зеркальная сеть. В файл
  `C:\Users\<имя>\.wslconfig`:
  ```ini
  [wsl2]
  networkingMode=mirrored
  ```
  затем в PowerShell `wsl --shutdown` и перезапустить PyCharm.
- **Windows 10** — правило брандмауэра. В WSL `hostname -I` → первые две
  части адреса + `.0.0/16` (например, `172.21.0.0/16`). В PowerShell от
  администратора:
  ```powershell
  New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" -Direction Inbound -Protocol TCP -Action Allow -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16
  ```

Галку «Accept connections from all network interfaces» в настройках
плагина не включать: трафик тогда идёт по локальной сети открытым текстом.

### 3.5. Правки — в просмотрщике PyCharm

В сессии `/config` → **Diff tool** → `auto`. Пункт появляется, только
когда агент подключён к IDE.

### 3.6. Интерпретатор — после E0-01

Когда в E0-01 появится виртуальное окружение: Settings → Python
Interpreter → Add Interpreter → On WSL → указать его. До этого шага
PyCharm будет подсвечивать импорты как неизвестные — это нормально.

## 4. Что уже лежит в репозитории для агента

| Файл | Что делает |
|---|---|
| `CLAUDE.md` | Загружается в каждую сессию: что за проект, где документы, правила кода, порядок работы. Короткий намеренно — детали агент читает из `docs/` сам |
| `.claude/settings.json` | Права агента, см. ниже |
| `.claude/skills/start-task/` | Команда `/start-task E0-01`: собрать контекст задачи и выдать план |
| `.claude/skills/close-task/` | Команда `/close-task`: чек-лист закрытия, документация, `PROGRESS.md` |
| `.gitignore` | Секреты, личные настройки агента, кэши, сборка документации |

### 4.1. Права агента — `.claude/settings.json`

| Правило | Зачем |
|---|---|
| `defaultMode: default` | Сессия стартует в режиме Manual, см. 4.2 |
| `blockReadsOutsideWorkingDirectories` | Агент не читает ничего за пределами папки проекта: ни домашнюю директорию, ни `/mnt/c` |
| `disableBypassPermissionsMode` | Режим «без подтверждений» выключен совсем — нельзя включить случайно |
| `Read(.env)`, `Read(.env.*)` | Секреты закрыты на чтение и запись, в том числе через выделение в PyCharm |
| `Read(!.env.example)` | …кроме шаблона, он должен быть в репозитории |
| `Read(**/secrets/**)` | На случай, если появится папка с ключами |
| `Edit(.idea/**)` | Агент не правит настройки PyCharm: часть из них IDE выполняет сама, это обход подтверждений |
| `Bash(git push *)` | Отправку в удалённый репозиторий делаешь только ты |

Честное ограничение: запрет на чтение срабатывает для файловых
инструментов и для команд, называющих файл по имени (`cat .env`). Скрипт,
который сам откроет `.env`, запрет не остановит — от этого защищает
песочница (раздел 6). От случайности правила защищают, от злого умысла —
нет.

Твои личные дополнения — в `.claude/settings.local.json` (он в
`.gitignore`). Туда же Claude Code сам пишет разрешения, когда ты
отвечаешь «да, и больше не спрашивать».

### 4.2. Режим подтверждений

На планах Pro, Max и Team сессия по умолчанию стартует в режиме **auto**:
действия проверяет не человек, а отдельная модель-классификатор. Для
этого проекта в `.claude/settings.json` выставлен режим **Manual**
(`default`): агент спрашивает перед каждой правкой и командой, а правка
открывается в просмотрщике PyCharm — видишь, что меняется, и учишь
Python на живом коде. Документация Claude Code советует Manual и для
работы из JetBrains.

Shift+Tab переключает режимы по кругу: Manual → accept edits (правки без
вопросов) → plan → снова Manual; auto, если доступен, стоит в круге
последним. Когда освоишься и будешь доверять процессу — переключайся на
время механической работы или убери строку `defaultMode` из настроек.

## 5. Первая сессия

```
cd ~/projects/seo-system
claude
```

1. Внизу должно быть `⏸ manual mode on`.
2. `/context` — в списке **Memory files** должен быть `CLAUDE.md`.
3. `/permissions` — должны быть видны правила из раздела 4.1.
4. Shift+Tab дважды, до `⏸ plan mode on`: в этом режиме агент только
   читает и планирует, файлы не трогает.
5. `/start-task E0-01` — агент прочитает `PROGRESS.md`, описание задачи,
   нужные документы и выдаст план.
6. Обсуждаешь план, правишь. Когда согласен — одобряешь: агент выйдет из
   режима планирования и предложит, как подтверждать правки. Выбирай
   вариант с ручным подтверждением.
7. По ходу правки открываются в просмотрщике PyCharm: смотришь,
   принимаешь или отклоняешь.
8. Критерии приёмки выполнены → `/close-task`. Агент прогонит проверки,
   обновит документацию и `PROGRESS.md`, предложит текст коммита.
9. Читаешь дифф документации, как дифф кода, говоришь «ок» — коммит.
10. `/clear` — и следующая задача с чистого листа.

Для задач E0 отдельное ТЗ не нужно: описания в `06-BACKLOG.md` хватает.
Для задач с E1 — сначала ТЗ в чате, см. `14-WORKFLOW.md` §3.

## 6. Песочница — позже, когда освоишься

Песочница — изоляция на уровне ОС: ограничения действуют на все
команды агента и их дочерние процессы, включая скрипты, которые сами
открывают файлы. Работает на WSL 2.

```bash
sudo apt-get install bubblewrap socat
```

Проверка AppArmor на Ubuntu 24.04+:
`sysctl kernel.apparmor_restrict_unprivileged_userns`. Если `0` или
ошибка «No such file or directory» — ничего делать не нужно.

Перезапусти `claude`, набери `/sandbox` — панель покажет, всё ли на
месте, и включит песочницу.

**Для нашего проекта обязательно:** `docker` с песочницей несовместим,
его нужно вывести из неё. Добавить в `.claude/settings.json`:

```json
{
  "sandbox": {
    "enabled": true,
    "excludedCommands": ["docker *"],
    "filesystem": {
      "denyRead": ["~/"],
      "allowRead": ["."]
    }
  }
}
```

`denyRead` и `allowRead` закрывают всю домашнюю директорию, кроме
проекта. Точка означает корень проекта только в настройках проекта — в
`~/.claude/settings.json` она значила бы другое.

Первое время песочница будет спрашивать разрешение на каждый новый
домен при установке пакетов — это нормально, ответы запоминаются.

Учти: команды, которые выполняются внутри песочницы, по умолчанию идут
без вопросов даже в режиме Manual — граница проведена на уровне ОС, в
этом и смысл. Правки файлов и запреты из раздела 4.1 работают как раньше.

## 8. Экономия токенов

- `/clear` между задачами — самое действенное. Каждый запрос тащит всю
  историю сессии.
- Конкретные запросы: «добавь валидацию в `sites/importers.py`,
  функция `parse_categories`» вместо «улучши импорт».
- `/model` — сильная модель для планирования и сложного, быстрая — для
  механической работы.
- `/usage` — расход, `/context` — что занимает контекст.

## 9. Если что-то не работает

| Симптом | Что делать |
|---|---|
| `claude: command not found` | Перезапустить терминал; проверить, что `~/.local/bin` в `PATH`; `claude doctor` |
| Плагин: «Cannot launch Claude Code» | Проверить Claude command из 3.3 и имя дистрибутива |
| `/ide`: No available IDEs detected | Раздел 3.4 |
| Esc не прерывает агента | Раздел 3.2, галка про фокус |
| Агент не видит `CLAUDE.md` | Запущен не из корня проекта — `pwd`, `cd ~/projects/seo-system` |
| Нет команды `/start-task`, в `/permissions` пусто | Сессия запущена не из корня проекта — выйти, `cd ~/projects/seo-system`, `claude` |
| Сессия стартует в auto, а не в Manual | Запуск не из корня проекта, либо строку `defaultMode` перебивает `.claude/settings.local.json` |
| С песочницей падает `docker` | `excludedCommands`, раздел 6 |
