# 00. Vision — зачем мы это строим

## Проблема

Линкбилдинг для convertio.co ведётся вручную двумя людьми через маркетплейс
Collaborator.pro. Вся информация хранится в Excel: 33 колонки, 568 строк
рабочей базы на 17.09.2026 и пул в 1494 кандидата на 23.09. Каждое
размещение требует ручного прохода по цепочке: найти площадку,
пробить в Ahrefs, посмотреть глазами сайт, проверить на серые тематики через
`site:`, посчитать цену, подобрать анкор, отправить заявку, дождаться статьи,
проверить её по 17 пунктам требований, после публикации проверить индексацию,
а потом периодически перепроверять, жива ли ссылка.

Четыре следствия, каждое из которых по отдельности терпимо, а вместе —
потолок роста:

1. **Человеческая ошибка накапливается.** Глаз замыливается на третьем десятке
   площадок, проверки пропускаются, статусы не проставляются.
2. **Нет памяти о том, что надо перепроверить.** Индексация, живость ссылок,
   актуальность цен — всё держится на «не забыть».
3. **Копирайтеры — узкое горлышко.** Заказ на 18 статей: за 3 дня пришло 2,
   одна из них отправлена на доработку. При целевых 100 размещениях в месяц
   этот канал не масштабируется в принципе.
4. **Выгорание.** Объём рутины на двоих при текущем методе превышает
   разумный рабочий день ещё до выхода на целевые показатели.

## Цель

Внутренний инструмент, который снимает механическую часть работы и оставляет
людям только решения:

- **100 размещений в месяц** стабильно, с потенциалом выше.
- Из них примерно **50 статей в месяц пишет система**, а не копирайтеры
  (обоснование цифры — см. `10-BASELINE-STATS.md`).
- Аудит площадки занимает минуты вместо 15–20, и его результат воспроизводим.
- Ни одна проверка не теряется: система сама напоминает, что просрочено.

## Пользователи

Два человека. Один (владелец проекта) пишет код и принимает финальные решения
по размещениям и статьям. Второй — партнёр, подключается при сомнениях и
спорных случаях. Мультитенантность, роли, права доступа — не нужны.
Аутентификация — минимальная, достаточно двух учётных записей.

## Метрики успеха

Измеримые, проверяемые, выводятся на дашборд:

| Метрика | Сейчас | Цель |
|---|---|---|
| Часов ручной работы на 1 размещение | 1.5–2 ч | < 20 мин |
| Размещений в месяц | единицы | 100 |
| Статей от системы в месяц | 0 | 50 |
| Доля черновиков, прошедших валидаторы с 1-й попытки | — | > 70% |
| Доля статей, принятых без правок | — | > 50% |
| Доля живых ссылок через 90 дней после публикации | неизвестна | > 95% |
| Пропущенных проверок индексации | неизвестно | 0 |

Отдельно: метрика «неизвестна» в двух строках — сама по себе проблема.
Первый эффект от системы — появление этих чисел.

## Нецели — что мы сознательно НЕ делаем

Список важен не меньше целей: он защищает от расползания.

- **Не SaaS.** Инструмент для двоих, не продукт на продажу. Никакой
  мультитенантности, биллинга, онбординга, публичного API.
- **Не обучаем свою модель и не делаем fine-tune.** Обоснование — ADR-005.
- **Не заменяем человека в финальном решении.** Система готовит, ранжирует,
  проверяет и обосновывает; «да/нет» по площадке и «принято» по статье
  говорит человек.
- **Не автопостинг.** Заявки на Collaborator отправляет человек, пока не
  будет доказано, что API это позволяет и что риск ошибки приемлем.
- **Не микросервисы, не Kubernetes, не своя инфраструктура метрик.**
  Монолит на одном VPS — см. ADR-010.
- **Не переписываем Excel один в один.** Часть колонок текущей таблицы —
  артефакты ручного процесса и в новой модели не нужны.

## Что считается провалом

Честный список сценариев, ради избежания которых написан раздел «Нецели»:

- Проект встаёт на 40% готовности, все возвращаются в Excel.
- Система построена, но ей не доверяют и всё перепроверяют руками.
- Генератор выдаёт статьи, которые площадки принимают, а Google — нет.
- Пятьдесят статей в месяц из одного пула фактов оказываются похожими
  настолько, что ссылочный профиль выглядит штампованным.

Последний пункт — единственный, который может навредить основному бизнесу,
а не просто потратить время. Поэтому требования к вариативности контента
вынесены в критичные (см. `05-CONTENT-SYSTEM.md`, раздел «Уникальность»).
