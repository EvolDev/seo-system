# 01. Глоссарий

Единый язык проекта. Названия таблиц и полей в коде должны следовать этим
терминам, а не изобретать синонимы.

## Основные сущности

**Продукт (product)** — продвигаемый сайт. Сейчас `convertio.co`. Clideo —
второй продукт параллельной кампании; в системе он равноправная сущность,
а не особый случай (см. ADR-007).

**Площадка / донор (site)** — внешний сайт, на котором мы размещаем статью со
ссылкой. Синонимы в старой таблице: «target», «площадка», «донор».
Каноническое название — площадка.

**Размещение (placement)** — факт публикации статьи со ссылкой на конкретной
площадке под конкретный продукт. У одной площадки может быть несколько
размещений, в том числе под разные продукты и в разное время.

**Ссылка (placement_link)** — конкретная ссылка внутри статьи. У размещения
бывает 1–3 ссылки на продукт. Имеет анкор, целевой URL, атрибут rel,
позицию в тексте и признак живости.

**Статья (article)** — текст размещения. Может быть написана площадкой по
нашему ТЗ, копирайтером или системой. Имеет версии.

**Целевая страница (target URL)** — страница продукта, на которую ведёт
ссылка. Например `convertio.co/mp4-mp3/`.

## Анкоры и ключи

**Анкор (anchor)** — текст ссылки.

**Типы анкоров** (в скобках — значение `anchor_type`):
- *прямой* (`exact`) — точное вхождение ключа («mp4 to mp3»);
- *разбавленный* (`diluted`) — ключ в составе фразы («use the mp4 to mp3
  converter»);
- *безанкорный (безанкорка)* — три подвида, как во вкладке
  «Распределение безанкорки»: бренд (`branded`: «Convertio»,
  «convertio.co»), голый адрес (`url`: «https://convertio.co/»),
  нейтральное слово (`generic`: «here», «this website»).

**Тип страницы (page_type)** — колонка Type файла анкоров: «Главная»,
«Основные разделы», «Одиночные форматы (xxx)», «Video (xxx-yyy)»,
«Audio (xxx-yyy)», «Остальное». Не путать с типом анкора.

**Ключ (keyword)** — поисковый запрос из мастер-таблицы «Распределение
анкоров». Имеет объём, целевой URL, категорию Tool и историю позиций.

**Tool-категория** — принадлежность ключа к типу страниц продукта:
`Main`, `Video`, `Audio`, `Image`, `Doc`. Определяет, какие анкоры уместны
для статьи конкретной тематики.

**Позиция (position)** — место целевой страницы в выдаче по ключу.
Ключи в позициях 4–25 — приоритет для продвижения. Топ-1–3 не трогаем.

**Недопокрытость** — состояние ключа, по которому размещено мало или ноль
ссылок. Приоритетный кандидат на новое размещение.

**Links Placed / Links Waiting** — сколько ссылок по ключу уже размещено /
находится в работе. В новой системе вычисляются из `placement_links`,
а не хранятся руками.

**Слот (slot)** — разрешённое количество ссылок на продукт в одной статье
на конкретной площадке. Поле `links_allowed`. Определяет, предлагать один
анкор или связку из двух.

## Аудит площадки

**Стоп-фактор** — условие безусловного отказа без взвешивания остальных
метрик. Полный список — `04-DOMAIN-RULES.md`.

**Гибкая зона** — набор факторов, которые оцениваются совокупно, а не по
порогу: DR, трафик, число ключей, тематика, цена, доля серости,
декларация особых тематик, судьба ссылки на Clideo.

**Предфильтр** — первый шаг массового аудита по полям выгрузки
Collaborator: основной язык английский, нет пометки «реклама», dofollow.
Бесплатный, без API и LLM. Дальше — сортировка, а не отсев.

**Пул кандидатов** — выгрузка каталога Collaborator с площадками, по
которым ещё не было решений. Отличается от рабочей базы, где лежат
решения и размещения.

**Серость / серые тематики** — присутствие в индексе площадки страниц по
темам: гэмблинг, форекс, займы, дейтинг, порно, наркотики и CBD,
рецептурные препараты, эссе-миллс. Измеряется долей от общего числа
проиндексированных страниц.

**Особые тематики (декларация)** — поле карточки Collaborator: какие
серые темы площадка **готова принимать**. Не то же самое, что серость:
это заявление, а не факт из индекса. Хранится в `sites.declared_topics`.

**Gray scan** — проверка площадки на серость через поисковые операторы
`site:domain "casino" OR ...` с подсчётом доли.

**DR (Domain Rating)** — метрика Ahrefs. Ориентир >50, не жёсткий порог.

**Вердикт** — результат аудита: `yes` / `no` / `borderline`.

## Контент

**Пул знаний (knowledge pool)** — база проверенных фактов, источников,
сравнений и анкорных конструкций, из которой собираются статьи.

**Факт (fact)** — атомарное проверенное утверждение с источником, датой
проверки и сроком годности.

**Анкорная конструкция (anchor pattern)** — образец предложения-носителя
ссылки, прошедший тест на извлечение и принятый человеком. Хранится как
шаблон синтаксической конструкции, а не как готовый текст для копирования.

**Тест на извлечение (extraction test)** — главная проверка качества
интеграции ссылки: если убрать анкор и крепящий фрагмент, должен исчезнуть
субъект, действие, объект или результат. Если смысл предложения сохраняется —
интеграция плохая.

**Валидатор (validator)** — детерминированная проверка статьи кодом
(позиция ссылки в символах, rel, количество ссылок, структура). Не LLM.

**Критик (critic)** — отдельный LLM-вызов с чистым контекстом, оценивающий
то, что нельзя проверить кодом: качество интеграции анкора, естественность
текста, соответствие тематике.

**Золотой набор (golden set)** — фиксированный набор заданий с известным
эталонным результатом. Прогоняется при каждом изменении промптов или правил,
чтобы поймать деградацию.

**Вариант промпта (prompt variant)** — одна из нескольких формулировок
системного промпта, между которыми идёт статистическое сравнение по доле
принятых статей.

## Технические термины

**run_id** — сквозной идентификатор, связывающий все действия системы в
рамках одной цепочки (аудит площадки → подбор анкора → генерация статьи →
проверка). Позволяет поднять историю одного размещения целиком.

**Снапшот (snapshot)** — запись метрики на дату. Метрики никогда не
перезаписываются, только дописываются.

**Проверка (check)** — запись в едином журнале проверок с типом, результатом
и датой следующей проверки. Основа всех напоминаний.
