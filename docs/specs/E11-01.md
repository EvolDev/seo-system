# ТЗ: E11-01 · Сделки Collaborator по кнопке и сверка с размещениями

**Эпик:** `docs/backlog/E11-ROUTINE.md` · **Зависимости:** E1-20 · **Фаза:** 2
**Дата:** 2026-11-08 · **Статус:** согласовано (направление — 08.11, детали
экранов — на показе)

Исследование, поля API и пробная сверка — `docs/specs/browser-plugin.md`.

## 1. Цель

Закрывать размещения Collaborator без ручного переноса. Система по кнопке
забирает сделки через официальный API, сама находит размещение каждой
сделки, заполняет пустые поля и показывает расхождения. Человек только
проверяет и решает.

## 2. Что входит и что нет

**Входит:**
- Клиент API Collaborator (`apps/integrations/collaborator/`):
  `GET /api/public/deal/list` постранично, заголовок `X-Api-Key`, ключ
  `COLLABORATOR_API_KEY` из окружения, только чтение. Ключ не попадает ни
  в логи, ни в ответы.
- Кнопка **«Обновить из Collaborator»** над «Размещениями». Обновление
  — задача очереди (`QueueTask`, `run_id`), ход и итог — всплывающим окном
  без перезагрузки: «186 сделок: 2 готовы к закрытию, 79 можно заполнить,
  13 расходится…» и ссылка на сверку. По расписанию не запускается —
  решение пользователя.
- Снимок сделок в базе: одна строка на сделку, обновляется при каждом
  нажатии (поля API, найденное размещение, когда забрали). Сверка
  работает и без повторного запроса.
- Сопоставление «сделка → размещение»:
  - продукт — по проекту Collaborator (`project.id` 144728 → Convertio,
    настройкой продукта);
  - площадка — по id карточки из `creator.url` против
    `sites.collaborator_url`, иначе по домену;
  - размещение — по номеру заявки, иначе по адресу статьи, иначе
    единственное размещение площадки с продавцом Collaborator. Иначе
    сделка уходит в сверку как неоднозначная.
- Экран **«Сверка с Collaborator»** в разделе «Работа», группы:
  - **Готовы к закрытию.** На Collaborator — Pending approval со статьёй,
    в системе — «Заявка отправлена» или «Написание статьи»;
  - **Можно заполнить** — пустые у размещения номер заявки, «Заплачено»
    (= Total), адрес статьи, анонс на главной (если анонс платный).
    Кнопка «Заполнить отмеченные»;
  - **Расходится** — анкоры, номер заявки, адрес статьи, «Заплачено», а
    также «на Collaborator опубликовано или отказ, в системе — другой
    статус». У каждого — «Взять из Collaborator» и «Оставить как в
    системе». Второе запоминается для этой сделки и поля, пока значения
    не изменятся;
  - **Нет в системе** — сделки без размещения, кнопка «Завести
    размещение».
- Блок **Collaborator** в панели размещения:
  - заявка, статус, Total и его состав, анонс, адрес статьи;
  - анкоры с ✓ или ✗ против ссылок размещения;
  - кнопка «Заполнить из Collaborator» — заполняет поля формы, но не
    сохраняет; дальше человек жмёт «Размещено» → «Сохранить».
- Фильтр **«Collaborator»** в «Размещениях»: «готовы к закрытию», «есть
  расхождения».

**Не входит:**
- проверка самой статьи на сайте, бесплатный анонс и таймер автоприёма
  (их нет в API) — E11-05;
- корзина — E11-06;
- индексация по расписанию — E11-07;
- Google-таблицы — E11-03;
- барыги — E11-04;
- обновление по расписанию — по решению пользователя, только кнопка;
- любая запись в Collaborator — API только читает.

## 3. Решение

- **Деньги.** «Заплачено» = `price` (Total) в центах, валюта из строки
  («EUR»). Total у всех 186 сделок равен сумме частей: размещение,
  написание, анонс, страховка. «Заплачено» размещения в счёте не трогаем
  (ADR-055).
- **Дата «Опубликовано» из Collaborator не берётся.** Её ставит статус
  «Размещено» (день закрытия, `Placement.save`). Пользователь иногда
  держит размещение до следующего месяца ради плана в 100. Дата публикации
  на Collaborator (`dateOfPlacement`) показывается только как справка.
- **Анонс.** В API есть только цена платного анонса (`priceAnnouncement`).
  Бесплатный анонс виден только на странице — это E11-05.
- **Анкоры.** Текст сравниваем через `apps.keywords.matching.normalize`,
  адреса — через `same_url`. Результат по каждой ссылке: ✓, «текст
  другой», «адрес другой», «лишняя в системе», «нет в системе».
  «convertio.co» и «https://convertio.co» — разные тексты, это
  расхождение. «Взять из Collaborator» переписывает ссылки размещения:
  ключ и вид — как в форме ссылки и загрузке размещений (ADR-069),
  регион — список размещения (ADR-075).
- **Статус.** Сделка Pending approval не меняет статус в системе сама —
  закрывает человек. Posted, Rejected или Withdrawn при другом статусе в
  системе — только расхождение с кнопкой. Источник смены статуса в
  истории (ADR-049) — новое значение или `upload`; решить на старте.
- **Блокировка правки (ADR-077).** Занятые другим размещения действия по
  отмеченным пропускают и пишут об этом.
- **Отмена.** «Заполнить отмеченные» и «Взять из Collaborator» пишутся
  через журнал загрузок (`set_config('seo.upload_id', …)`, ADR-060), чтобы
  «Отменить» работала, как у загрузок. Отдельный вид загрузки или своя
  таблица — решить на старте, с записью в ADR.
- **Схема.** Новая таблица снимка сделок (и, если нужно, решений
  «оставить как в системе») — миграцией, в `schema.sql`, перед
  применением — `sqlmigrate`.

## 4. Шаги реализации

0. Отдельная ветка и папка (git worktree), рабочий сервер на 8000 не
   трогаем. Дамп рабочей базы, её копия и второй сервер на :8002 (память
   `demo-on-db-copy`).
1. Клиент API и настройка проекта у продукта. `COLLABORATOR_API_KEY` — в
   `.env.example` и `docs/13-CONFIG.md`. Тесты с подменой httpx, без
   настоящих запросов.
2. Таблица снимка сделок: модель, миграция, `schema.sql`.
3. Задача обновления, кнопка, окно хода и итога.
4. Сопоставление и расчёт сверки — чистые функции с тестами.
5. Экран «Сверка с Collaborator» и действия с журналом.
6. Блок в панели размещения и «Заполнить из Collaborator».
7. Фильтр в «Размещениях».
8. ADR, справка, журнал изменений, браузерные проверки. Показ на копии
   (:8002). После «ок» — слияние, дамп, `! make migrate` руками
   пользователя, сверка таблиц.

## 5. Тесты

- Клиент: страницы до `pageCount`, 401 и 302 — понятная ошибка, ключ не
  виден в исключениях и логах; без ключа — сообщение «ключа нет».
- Сопоставление: номер заявки, адрес статьи (поддомен, `?srsltid`),
  единственный кандидат, два размещения на площадке (ADR-073), карточка
  против домена, чужой продукт.
- Сверка:
  - Pending approval и «Заявка отправлена» → «готовы к закрытию»;
  - пустые поля → «можно заполнить»;
  - разные значения → «расходится»;
  - «оставить как в системе» помнится, пока значения не изменятся.
- Действия:
  - заполняются только пустые поля;
  - «Заплачено» из счёта не трогается;
  - занятые размещения пропускаются;
  - повторное нажатие ничего не меняет;
  - «Отменить» возвращает как было.
- Анкоры: регистр и пробелы, `/` в конце, лишняя ссылка, недостающая,
  три ссылки.
- Браузерные: кнопка и окно итога, экран сверки, блок в панели и
  «Заполнить».

- [ ] Цифры на копии базы от 08.11 сходятся с пробной сверкой:

  - [ ] «Можно заполнить»: 79 номеров заявок, 12 платных анонсов, 4
        адреса статей, 2 «Заплачено»;

        talkandroid.com.
- [ ] «Заполнить отмеченные» заполняет только пустое, не трогает

      «Отменить» возвращает как было.
- [ ] «Оставить как в системе» убирает расхождение, и при следующем
      обновлении оно не возвращается, пока значения не изменятся.
